## A. 戦闘演出 — 62点

### 良い点(実際に見て確認)
- **スキルカットインは商用水準**。斜めの光帯 + 立ち絵 + 技名(`shots/08-result.png` の「光条の矢」)は見栄えがする。
- 行動中ユニットのシアン発光リング、撃破時の灰色化、レアリティ別カード枠(SSR金/UR虹)は一目で格が分かる。
- HPバー・行動ゲージ・必殺ゲージ・進捗バー・1x/2x/4x・一時停止・スキップが揃っている。
- コンソールエラー0件。420px幅でも横スクロールが出ない。

### 致命的な問題
**P0: 戦闘開始から約7秒、ダメージが1つも出ない。**
`shots/06-battle-05.png` / `06-battle-10.png` の時点で敵3体は全員HP満タン。その間ログに流れるのは:

```
天城 彼方 の 星護の誓約!
黒鉄 巌 に シールドが張られた!   ← 5人分
北斗 の 攻撃上昇!                ← 5人分
黒鉄 巌 の 必殺ゲージが 15% 変動! ← 5人分
天城 彼方 は 再生 で 0 回復!      ← 値0のイベントがそのまま見えている
```
**ログ20行以上がバフの羅列**で埋まり、プレイヤーが見たい「殴った・倒した」が画面外へ押し出される。
オートバトルは「見ている時間」が体験の全てなので、これは演出の問題ではなく**体験の破綻**である。

**P0: 「再生 で 0 回復」が繰り返し表示される。** 値0のイベントが送出されており、
意味のない行が大量に混ざる。プレイヤーは「バグっている」と受け取る。

**P1: 戦場が広すぎて空白が目立つ。** 敵3体が中央上に寄り、左側と画面下1/3が黒い空白。
「戦場」に見えない。敵列と味方列の水平位置も揃っていない。

**P1: 状態異常アイコンが判読不能。** カード下部の緑チップは実寸で潰れており、
何の状態が何ターン残っているのか読めない(`06-battle-10.png`)。

**P1: ログの括弧地獄。** 「体当たり! 黒鉄 巌 に 21 ダメージ!(効果はいまひとつ...)(シールドが 21 肩代わり)」
のように1行へ情報を詰めすぎている。

## B. ゲーム性 — 32点 (最大の問題)

### 実測: 初期編成(全員Lv1)のまま第1章から順に各3回挑戦

| ステージ | 勝率 | 平均行動数 | 味方生存 |
|---|---|---|---|
| ch1-1 〜 ch2-4 (8ステージ) | **すべて 3/3** | 8〜27 | **すべて 5/5** |
| ch1-5 (BOSS) | 3/3 | 21 | 5/5 |
| ch2-5 (BOSS) | 3/3 | 32 | 3/5 が1回だけ |

**全30戦30勝。味方が1人でも落ちたのは最終ボスで1回だけ。**

原因は3つ。
1. **報酬EXPが難易度を常に追い越している。** 順番に進めるだけで味方Lvが敵Lvに並ぶか上回る
   (ch2-5到達時に味方Lv21 vs 敵Lv19〜20)。育成の判断が発生しない。
2. **敵のHPと火力が低すぎる。** ch1-1 の敵は総HP900、対して味方は総HP4,300。
   スライムの体当たりが21ダメージ(味方HPの2%)では脅威になりようがない。
3. **ステージ開放制御が無い。** 第1章を飛ばして第2章へ直行できる。`STAGE_LOCKED` という
   エラーコードが `shared/src/api.ts` に定義済みなのに未使用。

結果として、**設計書§50が掲げる「編成を研究する」体験が一度も起動しない。**
属性相性を考える必要も、ロールを揃える必要も、AI戦術を選ぶ必要もない。
「強いキャラを並べて放置」で全クリできる。これはこのジャンルで最も避けねばならない状態である。

### さらに: 本作の看板が未実装
設計書§13はキャラクターコンボを「本作の重要システム」と明記している。
現状 `data/combos/` は空で、`hitori` と `momiji` の `combos: ["network_link"]` は
**ID文字列が表示されるだけ**。編成画面にも発動コンボ欄が無い(設計書§40違反)。
「誰と組ませるか」で勝敗が決まるゲームを名乗る以上、ここが空なのは看板の未達である。

## C. キャラクター — 78点

- 10体の役割分化は良い。黒鉄(N)が壁性能最高、雫(N)が全体解除最速、北斗(R)が対闇火力最高、
  天城(UR)は万能だが各分野では専門職に劣る — **レアリティ≠強さ**の約束(§4/§44)は数値上守られている。
- 仮キャラ画像が想像以上に機能している。紋章1文字 + 配色 + パターン6種で10体を完全に見分けられる。
- **減点理由**: 上記の通り戦闘が作業なので、その役割分化がプレイ中に体感できない。
  設計が数値に存在するのに、プレイヤーに届いていない。コンボ未実装で関係性も乗っていない。

## D. UI/UX — 74点

### 良い点
- ダンジョン画面の各ステージ説明が秀逸(「雫のような解除役を入れると難易度が一段下がる」等)。
  何を試すべきかを言葉で教えている。
- 編成画面の属性/ロール構成バー、キャラ画面の絞り込み4種+ソート、図鑑のシルエット表示。
- API停止時も白画面にならず日本語エラー + 再試行が出る。

### 問題
- **P0: 推奨戦力が嘘をつく。** ダンジョン画面は全ステージに「推奨戦力 1/3/5/7/9 **(十分)**」と表示。
  一方パーティ戦力は 3,435。データ側は「推奨**レベル**」を入れているのに UI は戦力と比較しており、
  **Lv1でも最終ボスが「十分」と表示される**。プレイヤーを騙している(`data/dungeons/*.json` の
  `recommendedPower` と `shared/src/types.ts` の定義が曖昧なまま各担当が別解釈した)。
- **P1: 編成スロットのラベル重なり。** 「SLOT 1」の文字に属性チップが重なり、
  レアリティバッジが×ボタンに重なって潰れている(`shots/04-party.png`)。
- **P1: HOME画面の下半分が空。** 最初に開く画面の情報密度が低い。
- **P1: 編成画面に発動コンボ/属性相性の実効果が出ない**(§40)。構成の「数」だけでは、
  それが戦闘で何をもたらすのか分からない。

## E. 技術的健全性 — 88点

- サーバ権威は徹底されている。戦闘開始リクエストは `stageId` と編成uidのみを受け、
  所持キャラであることを毎回DB再確認。偽装uidも重複編成も拒否を実測確認。
- 決定論: 同シード同入力でログ完全一致。`BattleLog` にシード記録済みでリプレイ可能。
- テスト62件パス、client/server 両方の型チェックがエラー0、データバリデータで参照切れ0。
- SQLは `db/repository.ts` に集約されDB差し替え可能。
- **減点**: `BattleLog.createdAt` だけが決定論を破る(ハッシュ比較ができない)。
  `/api/master` の `aiProfiles` に敵AIが混在し、クライアントがID接頭辞で除外している
  (ID規約が変わると壊れる)。0値イベントの送出。

## このゲームが「面白い」と言えるために足りない一番大きなもの

### **「負ける可能性」と「それを編成で覆す快感」**

現状このゲームには失敗が存在しない。失敗しないゲームに研究は生まれず、研究の無い
編成画面はただの着せ替えである。設計書§50が描く体験
「育成 → 転生 → 自分好みのビルド → 別の探索者と組み合わせる → コンボ発見」
の全ての起点は「**そのままでは勝てない壁**」であり、それが今ひとつも無い。

演出・データ・技術基盤は既に高水準にある。足りないのは**難易度**と、
それを乗り越える手段としての**コンボ**である。この2つが入った瞬間に、
既に存在する10体の役割分化・23種のAI・属性相性が全部意味を持ち始める。
