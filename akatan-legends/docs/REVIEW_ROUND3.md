## 新キャラクター「孤月 紅葉(幽波紋)」の評価

### 実装当初は「罠キャラ」だった(修正済み)

ユーザーご本人の探索者であり、看過できない問題があった。実測(各300戦):

| 編成 | 勝率 |
|---|---|
| 既定(紅葉SR入り) | 67% |
| 紅葉SR→孤月紅葉URに差し替え | **52%** |
| 速度編成(孤月紅葉入り) | 59% |
| 同編成で孤月紅葉→炎司SSR | **71%** |

**彼女を入れた編成はすべて、入れない同編成より弱かった。** 与ダメ比12〜20%は
5人パーティの公平分20%を下回り、「脆いが火力で釣り合う」というガラスキャノンの
前提が成立していなかった。原因は3つで、すべて対処した。

1. 行動回数は多いのに1行動あたりの火力が低い
   → 攻撃力 116→132、通常攻撃 0.55×2 → 0.60×3、時飛ばし 0.55→0.78
2. 「妨害」が実質ただの遅延で、被ダメージを減らせていない
   → 時飛ばしは元ネタでは「その間相手は行動できない」能力。ゲージ削りに加えて
     STUN 1ターン(35%)を乗せ、手番そのものを奪うようにした
3. 予知シールドが手遅れになってから張られる
   → AIの発動条件を ALLY_HP_BELOW 45 → 75 に緩め、SELF_HP_BELOW 85 の専用ルールを
     追加。全キャラ最低HPなので1発貰ってからでは遅い

### 修正後の姿

| 場面 | 生存率 | 与ダメ比 |
|---|---|---|
| 通常ステージ(敵5体) | 100% | **43〜50%**(公平分の2倍以上 = チーム最大火力) |
| ボス戦 | 15〜44% | 27〜38%(脆いが仕事はする) |

**「集団戦では最強、ボスには脆い」**という一貫したガラスキャノンになった。
ボス戦の勝率は既定編成と同等(67%)なので、入れれば勝てるわけではない。
設計書§44の「レアリティだけで強さを決定しない」も守られている。

### 設定の反映

キャラシの能力値が素直に数値へ落ちている(DEX18→全キャラ最速のSPD150、
こぶし90→3連撃の通常攻撃と高クリティカル、STR7/CON10/HP10→全キャラ最低のHP/DEF)。
説明文に「別の並行世界から来た」「独への想いは何ひとつ変わらない」という核が
入っており、口癖「独君どこだ〜い♡」の空気感も出ている。
立ち絵を持つ初のキャラで、キャラ一覧で他のプロシージャル生成キャラの中から
明確に際立つ。UR虹枠と虚属性チップも正しく表示される。

コンボ相手の「電子 独(幽波紋)」は未実装だが、`PlannedCharacterDef` の仕組みにより
**IDを生で出さず「電子 独(幽波紋)(実装予定)」と名前で表示**される。

## A. 戦闘演出 — 84 → 86点

- リザルトに **DROPS** セクションが加わり、装備・素材・チケット・キャラ入手が
  レアリティ付きで表示される。勝敗 → EXP/GOLD → レベルアップ(ステータス上昇の内訳) →
  ドロップ → MVP という流れが1画面で完結する
- 装備の特殊効果は `fx: "equip:*"` の規約で控えめな専用演出が出る。
  スキルより控えめ・コンボより地味という格付けが適切
- **減点**: 通常ステージが短いため必殺技や覚醒を見る機会が少ない。戦場の空白も残る

## B. ゲーム性 — 88 → 88点(据え置き)

### 良くなった点
- **ガチャ**: 排出率(UR4%/SSR12%/SR20%/R30%/N34%)を常に全件公開。天井60連、
  10連のSR以上保証、ピックアップ。重複は素材へ変換され「完全なハズレ」にならない
  (設計書§27)。抽選はすべてサーバ側(§37)
- **ハクスラ**: 装備ベース18種 × Prefix12 × Suffix12 + ランダム値幅 + 特殊効果。
  同じ名前でも性能が違うという§22の構造が成立している
- **ドロップ**: 5テーブル。ボスほど高レア率とキャラドロップ率が上がり、
  「何も出ない」枠もあるので出たときの価値が保たれている

### 据え置きの理由(残る課題)
- **第2回からの指摘が未解決**: 通常ステージ6つが依然として勝率100%・戦闘不能0。
  ボスは壁として機能しているが、雑魚戦は消化試合のまま
- **装備を掘る動機がまだ弱い**: 序盤のドロップ率が低く、数戦しても所持装備1件。
  「複数の装備を比べて選ぶ」という体験が始まるまでが遠い
- 転生・覚醒の育成分岐(Phase 2)が未実装なので、同じキャラは今も同じ性能

## C. キャラクター — 90 → 92点

- 11体(N2/R2/SR3/SSR2/UR2)。コンボ7種(PAIR/TRIO/TAG)
- 孤月紅葉の追加で「立ち絵を持つキャラ」という表現の幅が増えた
- **減点**: 転生が未実装なので、設計書§19の「同じキャラでも別の育て方」はまだ不在

## D. UI/UX — 86 → 88点

- **SUMMON画面**: 排出率を隠さない。天井の残り回数を明示。残高不足の理由を表示
- **EQUIPMENT画面**: スロット/レアリティ/アイテムLvの絞り込みと4種ソート。
  装着前後の比較を `現在値 ▶ 装着後値 (+n/-n)` で色分け表示し、
  他の装備を外すことで下がるステータスも正しくマイナス表示される
- 未実装キャラも素材も**IDを生で出さず名前で表示**される
- 幅1280/420ともに横スクロールなし。コンソールエラー0
- **減点**: 戦場レイアウトの空白(第2回からの継続指摘)

## E. 技術的健全性 — 93 → 94点

- 戦闘エンジンのテスト **98件**(装備の特殊効果14件を追加)。
  `specials` 未指定なら乱数消費が1回も増えないことを直接検証し、決定論の
  後方互換を担保している
- 統合テスト **39/39**(3回連続で安定)
- DBを v2 へ移行。`PRAGMA user_version` ベースなので既存セーブは壊れない
- 装備生成はシード付きの決定論的生成。同じシードなら同じ装備が再現できる
- オフライン単体版と本体で**戦闘計算・育成計算・装備生成のモジュールを共有**しており、
  「単体版では勝てるのに本体では負ける」事故が構造的に起きない

### 開発中に見つけて直した実バグ
- 装備バナーの10連が `entries[0]` 決め打ちで**常に武器しか出なかった**(バックエンド)
- ガチャのオーバーレイにスクロールが無く、10連サマリーで**閉じるボタンが画面外に
  押し出されていた**(フロント)
- オフライン単体版の `getMaster` が素材と未実装キャラを返しておらず、
  **重複変換で素材IDが生表示**されていた(統括)
- 統合テストの「レベルアップでステータスが伸びる」判定が、ループの終了条件は
  「誰か」なのにステータス比較は固定で1体目を見ており、**まれに誤って失敗**していた(統括)
