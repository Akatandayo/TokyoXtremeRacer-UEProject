# 覚醒 — 批評基準（合格ラインは「配信できる」こと）

この文書は批評担当のためのものです。**目標は褒めることではなく、落とすことです。**
「Web ページとしてはよくできている」は不合格。判定は常に
**「App Store / Google Play に並んでいる和風RPGとして、これに課金する気になるか」**。

## 採点（各 10 点・合格は全項目 8 点以上、かつ致命が 0 件）

| # | 項目 | 見るところ |
|---|------|-----------|
| 1 | 第一印象 | 起動から3秒で「アプリだ」と感じるか。Web サイト臭さ（素の `alert`、リンクの青、ブラウザ由来の見た目）が残っていないか |
| 2 | 触り心地 | 44px 未満のタップ領域 / 押下の無反応 / 取りこぼし / 遅延。実際に座標をタップして確かめる |
| 3 | 動きの質 | 60fps か。`width`/`top`/`left` のアニメーションが残っていないか。`prefers-reduced-motion` が効くか |
| 4 | 画面遷移と迷子 | 「今どこにいて、どう戻るか」が常に分かるか。ハード戻るで壊れないか。深い階層から抜けられるか |
| 5 | 戦闘の手応え | 殴った感触があるか。何が起きたか演出だけで分かるか。2戦目以降ダルくないか（スキップ・短縮） |
| 6 | キャラクリエイト | 迷わず1体作れるか。作ったものが強いか弱いか分かるか。作って戦うまで途切れないか |
| 7 | ゲームとしての中身 | もう1回やりたくなるか。支配的な戦術・死に技がないか。AI が読み合いの相手になるか |
| 8 | 壊れにくさ | 想定外の操作（連打・途中で戻る・空入力・巨大画像・容量超過・オフライン）で黙って壊れないか |
| 9 | 画面サイズ耐性 | 360x640 / 390x844 / 430x932 / 768x1024 で破綻しないか。safe-area・横向き |
| 10 | 仕上げ | 文言の統一、日本語の質、誤字、余白の揃い、空・読込中・エラー状態のデザイン |

## 致命（1件でもあれば即不合格。点数に関係なく）
- JavaScript 例外が出る／画面が白くなる／操作不能になる
- セーブデータが消える・壊れる・黙って保存に失敗する
- 横スクロールが発生する
- 戦闘が決着しない、または勝敗が誤っている
- 戻る操作で状態が壊れる

## 批評のやり方（守ること）
- **スクリーンショットを撮り、Read ツールで自分の目で見てから書く。** コードを読んだだけの指摘は禁止。
- 指摘は必ず **「どのファイルの、何が、なぜ駄目で、どうすべきか」** の形にする。感想を書かない。
- 再現手順を書く。座標・操作順・期待と実際。
- 良い点は 3 行以内。**残りは全部なおすべき点に使う。**
- 最後に必ず **合格 / 不合格** と、**各項目の点数**、**次の周回で最優先に直すべき 5 件**を出す。
